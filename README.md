# مدارس سما التكنولوجيا للتميز والإبداع — بوابة الاستعلام عن الشهادات

موقع عربي باتجاه RTL لمدرسة أردنية، مبني باستخدام **HTML5 وCSS3 وJavaScript فقط**. يعمل مباشرة على GitHub Pages، بما في ذلك روابط المستودعات مثل `https://username.github.io/repository-name/` والنطاقات المخصصة. لا يتطلب بناءً أو تثبيت حزم أو خادم تطبيقات أو قاعدة بيانات أو مفاتيح API.

## تنبيه مهم حول خصوصية الملفات

**الملفات المنشورة على GitHub Pages متاحة للعامة. البحث بالرقم الوطني ليس مصادقة ولا يوفّر أي تحكم في الوصول.** يستطيع من يعرف أو يخمّن رابط ملف PDF الوصول إليه مباشرة، ويمكن نسخ الملفات ومشاركتها وفهرستها. إخفاء المجلد، عدم عرض قائمة الملفات، أو التحقق من الرقم في JavaScript لا يحميها. وقد تكون الملفات وأسماؤها ظاهرة أيضاً في المستودع العام وتاريخه.

لا تنشر مستندات شخصية أو سرية، ولا ملفات تحتوي على بيانات طلاب، إلا إذا كان نشرها للعامة مناسباً ومصرحاً به. للملفات السرية، استخدم استضافة تدعم التحقق من الهوية والتفويض على الخادم؛ GitHub Pages وحده لا يدعم ذلك. حذف ملف من الموقع لاحقاً لا يزيل بالضرورة نسخه أو تاريخه أو ذاكرات التخزين المؤقت.

التطبيق لا يخزن الأرقام الوطنية في `localStorage` أو `sessionStorage` أو ملفات تعريف الارتباط، ولا يرسلها للتحليلات أو الخدمات الخارجية، ولا يسجلها في وحدة التحكم. الخطوط والشعار محليان. يبقى الرقم جزءاً من اسم الملف في طلب HTTP إلى الاستضافة، وفي رابط PDF عند فتحه؛ قد تسجله الاستضافة أو يحفظه سجل المتصفح عند فتح الملف أو تنزيله. لا يوضع الرقم في معاملات استعلام رابط الصفحة.

لا يحتوي المشروع على مستندات طلاب تجريبية منشورة. أضف ملفاتك المناسبة للنشر إلى `pdfs/` قبل الاستخدام الفعلي. الاختبارات تنشئ ملفات PDF مصطنعة في الذاكرة فقط، ولا تضيف مستندات إلى الموقع.

## كيف يعمل البحث؟

1. يُدخل المستخدم الرقم الوطني كسلسلة نصية؛ تبقى الأصفار في البداية محفوظة.
2. يُسمح بالأرقام الإنجليزية `0–9` فقط، بما فيها اللصق. تُرفض الحروف والمسافات والإشارات والفواصل والأرقام العربية `٠١٢٣` بدلاً من تحويلها بصمت إلى رقم آخر.
3. يُتحقق من الطول المحدد، وهو 10 أرقام افتراضياً.
4. يُنشأ عنوان نسبي مثل `./pdfs/1234567890.pdf`، ثم يُرسل طلب **HEAD فقط** إلى نفس الاستضافة للتحقق من وجوده دون تنزيل محتوى الملف.
5. عند التأكد، يظهر زرا العرض والتحميل. لا تظهر روابط PDF للمدخل غير الصالح أو الملف المفقود.

لا توجد قائمة أرقام أو فهرسة للمجلد أو استخدام لواجهات نظام الملفات في المتصفح. **إضافة `1234567890.pdf` إلى مجلد `pdfs/` ثم نشر التغيير تجعل إدخال `1234567890` يجد الملف، دون تعديل JavaScript.**

يعامل التطبيق الاستجابات كما يلي:

| الاستجابة                                                                         | النتيجة            |
| --------------------------------------------------------------------------------- | ------------------ |
| `200` بنوع PDF أو binary مقبول وحجم غير صفري إن ذُكر                              | نجاح               |
| `404` أو `410`                                                                    | الملف غير موجود    |
| `403`، `405`، `429`، `5xx`، التحويلات، صفحة HTML برمز `200` أو استجابة غير متوقعة | خطأ أثناء التحقق   |
| انقطاع الاتصال أو تجاوز مهلة 15 ثانية                                             | رسالة تعذر الاتصال |

أنواع المحتوى المقبولة: `application/pdf` و`application/x-pdf` و`application/octet-stream`. فحص HEAD يتحقق من البيانات الوصفية وليس من سلامة محتوى PDF؛ يجب على مسؤول الموقع رفع ملفات PDF صالحة. الاستضافة التي تحجب HEAD أو لا ترسل نوع محتوى مناسباً ستعرض رسالة خطأ، ولا يحاول الموقع تنزيل الملف كاملاً كحل بديل. GitHub Pages يدعم HEAD وملفات PDF الثابتة.

أثناء الطلب يُعطّل زر البحث وتُمنع الطلبات المكررة. تعديل الإدخال يلغي الطلب الجاري بواسطة `AbortController` ويزيل الروابط والمعاينة والنتائج السابقة فوراً. فحص تسلسل الطلبات يمنع ظهور استجابة قديمة بعد بحث أحدث. يُعاد تفعيل الزر في جميع حالات الانتهاء.

## تغيير اسم المدرسة والشعار والإعدادات

عدّل `CONFIG` في أول `js/script.js`:

```js
const CONFIG = Object.freeze({
  schoolName: "مدارس سما التكنولوجيا للتميز والإبداع",
  logoPath: "./assets/school-logo.jpg",
  nationalIdLength: 10,
  requestTimeoutMs: 15000,
});
```

- الاسم يحدّث الترويسة والتذييل وعنوان الصفحة تلقائياً. لتحديث محتوى HTML الأولي أيضاً، غيّر الاسم في `index.html` ووصف الصفحة.
- الشعار الحالي في `assets/school-logo.jpg`. لاستبداله، ضع الصورة الجديدة بالاسم نفسه، أو أضف صورة محلية أخرى وحدّث `logoPath` وروابط الصور وأيقونة الموقع `<link rel="icon">` في `index.html`. استخدم دائماً مساراً نسبياً يبدأ بـ `./`. عند تعذر تحميل صورة مخصصة، يُستخدم الشعار المحلي الافتراضي.
- اضبط `nationalIdLength` لعدد الأرقام المطلوب، أو اجعله `null` لتعطيل الطول الثابت والسماح من رقم واحد إلى 64 رقماً. الحد الأعلى 64 مقصود لمنع إدخال طويل جداً؛ لا تغيّر الإدخال إلى `type="number"`.
- عدّل المهلة بالمللي ثانية باستخدام `requestTimeoutMs`.

## إضافة ملفات PDF

1. ضع ملف PDF صالحاً داخل مجلد `pdfs/` مباشرة.
2. طابق الاسم مع الرقم الوطني **حرفياً**، بأرقام إنجليزية وامتداد صغير `.pdf`؛ مثال `0123456789.pdf`.
3. لا تستخدم مسافات أو بادئات أو لاحقات أو `.PDF`؛ أسماء ملفات GitHub Pages حساسة لحالة الأحرف.
4. احتفظ بالصفر الأول في اسم الملف إذا كان جزءاً من الرقم. لا تفتح الأرقام في جدول بيانات يحوّلها إلى أعداد ويفقد الأصفار.
5. ادفع الملفات إلى الفرع المنشور وانتظر اكتمال النشر. لا تعدّل `script.js` ولا تنشئ قائمة أسماء.

ملف واحد لكل رقم. لاستبدال مستند، استبدل الملف بنفس الاسم وأعد نشره. البحث لا يخزن استجابة HEAD محلياً، لكن شبكات التوزيع والمتصفح قد تحتاج بعض الوقت لتحديث الملف بعد النشر.

## النشر على GitHub Pages

1. أنشئ مستودع GitHub وأضف محتويات هذا المجلد إلى جذره، مع الملفات المخفية `.nojekyll` و`.gitignore`.
2. ادفع الملفات إلى الفرع `main`، وأضف ملفات PDF المصرح بنشرها.
3. في المستودع افتح **Settings → Pages**.
4. في **Build and deployment** اختر **Deploy from a branch**.
5. اختر `main` والمجلد **`/ (root)`** ثم **Save**.
6. انتظر اكتمال النشر وافتح الرابط الذي يظهر في Pages، عادةً `https://username.github.io/repository-name/`.
7. اختبر رقماً له ملف وآخر لا يوجد له ملف، ثم جرّب العرض والتحميل على هاتف.

لا تحتاج إلى GitHub Actions مخصص أو npm أو PHP أو قاعدة بيانات. ملف `.nojekyll` يتيح نشر الملفات كما هي دون معالجة Jekyll. حافظ على المسارات النسبية ولا تستخدم `/pdfs/...` أو `/css/...`؛ الشرطة المائلة الأولى ستتجاوز اسم المستودع. يعمل نفس المشروع أيضاً مع نطاق مخصص مضبوط من إعدادات GitHub Pages. راجع حدود GitHub الحالية لحجم الملفات والمستودع عند رفع مستندات كبيرة.

## التجربة محلياً

من داخل مجلد المشروع، شغّل خادماً ثابتاً بسيطاً. على جهاز مثبت عليه Python:

```sh
python -m http.server 8000
```

على Windows يمكنك أيضاً استخدام:

```powershell
py -m http.server 8000
```

ثم افتح `http://localhost:8000/`. لإيقاف الخادم اضغط `Ctrl+C`. يمكن استخدام خادم المعاينة المدمج في محررك بدلاً من Python بشرط أن يدعم HEAD ويرسل نوع PDF الصحيح. خادم التجربة محلي فقط، ولا يُستخدم لتشغيل الموقع على GitHub Pages.

**لا تفتح `index.html` بالنقر المزدوج عبر `file://`.** هذا البروتوكول لا يتيح طلبات HTTP HEAD المطلوبة، وسيعرض الموقع رسالة توضح ضرورة استخدام HTTP أو GitHub Pages. لا يستطيع JavaScript قراءة مجلد `pdfs/` من نظام الملفات ولا يحتاج إلى ذلك.

## العرض والتحميل

- زر «عرض الشهادة» يفتح معاينة متجاوبة داخل الصفحة بعد التحقق من الملف فقط، مع زر إغلاق وإمكانية الإغلاق بمفتاح Escape.
- رابط «فتح الشهادة في نافذة جديدة» ظاهر دائماً بجوار المعاينة، ويفتح باستخدام `noopener noreferrer`.
- بعض متصفحات الهواتف أو إعدادات المتصفح لا تدعم عرض PDF داخل iframe. عندما يعلن المتصفح عدم دعمه، تظهر رسالة بديلة مباشرة. لا يمكن الاعتماد على حدث تحميل iframe لمعرفة أن PDF عُرض بنجاح في جميع المتصفحات، ولذلك يبقى رابط النافذة الجديدة متاحاً دائماً.
- زر «تحميل الشهادة» رابط من نفس النطاق بصفة `download` واسم PDF الأصلي. قد تفتح بعض متصفحات الهاتف الملف أولاً؛ استخدم خيار الحفظ أو المشاركة في المتصفح في هذه الحالة.
- الملف قد يُحذف أو الاتصال قد ينقطع بعد نجاح HEAD؛ رابط البديل والتحميل يساعدان عند فشل المعاينة. البحث لا يشكل ضماناً لإتاحة الملف لاحقاً.

## تخصيص التصميم والنصوص

- الألوان والخط والظلال والمتغيرات الأساسية موجودة في `:root` داخل `css/style.css`.
- الخط المستخدم Tajawal، مستضاف محلياً بوزنين 400 و700. ترخيصه في `assets/fonts/OFL.txt`.
- الرسائل الديناميكية في `MESSAGES` داخل `js/script.js`، والنصوص الثابتة والأسئلة الشائعة في `index.html`.
- التصميم يدعم الجوال والأجهزة اللوحية وسطح المكتب، والتنقل بلوحة المفاتيح، ورسائل `aria-live`، وحالة التركيز الظاهرة، و`prefers-reduced-motion`.
- لا تضف تحليلات أو خدمات خارجية تسجل الأرقام أو روابط PDF. استخدم APIs آمنة مثل `textContent` عند إضافة نصوص ديناميكية.

### اختبارات متصفح آلية اختيارية

الاختبارات تحتاج Node.js 22+ و`playwright-core` ومتصفح Chrome أو Edge محلياً **للتطوير فقط**؛ هذه الأدوات ليست تبعيات الموقع ولا تدخل في النشر. لا يحتاج الموقع إلى Node.js لتشغيله.

مثال PowerShell، يثبت أداة الاختبار في مجلد مؤقت خارج المشروع:

```powershell
npm.cmd install --prefix "$env:TEMP/school-portal-qa" --no-save --no-package-lock playwright-core
$env:PLAYWRIGHT_CORE_PATH = "$env:TEMP/school-portal-qa/node_modules/playwright-core"
node tests/portal.spec.cjs
```

يمكن تعيين `BROWSER_PATH` لمسار متصفح Chromium مختلف. الاختبارات تشغّل خادماً مؤقتاً على loopback وتغلقه تلقائياً، وتختبر تحت مسار مستودع، مع ملفات مصطنعة في الذاكرة. صور المعاينة تُحفظ داخل `test-results/` المتجاهل في Git. لا تضف ملفات الاختبار المصطنعة إلى `pdfs/`.

لتضمين تدقيق وصول آلي اختياري وفق WCAG، ثبّت `axe-core` أيضاً في نفس مجلد أدوات الاختبار، واضبط `AXE_CORE_PATH` إلى ملف `axe-core/axe.min.js` قبل تشغيل الاختبارات. التدقيق الآلي مكمل للمراجعة البصرية واختبار لوحة المفاتيح، ولا يضمن وحده التوافق الكامل مع كل تقنيات المساعدة.
